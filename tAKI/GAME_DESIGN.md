# tAKI 企画書

- 作成日：2026-10-18
- 用途：ゲームジャム向けの企画・実装方針の共有
- 開発時間：約5時間
- 開発環境：Unity 2022.3 LTS（2022.3.62f3）／URP 14.0.12
- 状態：2026-10-18にユーザーが仮方針の採用とWindows公開を決定し、実装を開始。本文の基本案・候補・仮仕様は初回実装に採用し、数値はプレイテストで調整する。

## 1. コンセプト

**秋を集めて、滝をのぼれ。**

滝を流れ落ちるA・K・Iの3種類のアイテムを拾い、上昇する勢いを得て頂上を目指す3Dアクションゲーム。
弱い重力と遅い落下によって次のアイテムを狙う時間を作り、連続取得とセットボーナスで勢いよく駆け上がる。

ゲームジャムのテーマ「あき」を、秋のアイテムと、タイトルや画面表示に含まれるA・K・Iで表現する。

| 表記          | 意味・使用箇所                             |
| ------------- | ------------------------------------------ |
| `tAKI`        | タイトル。「滝」と「あき」を掛け合わせる   |
| `A`・`K`・`I` | 流れてくる3種類のアイテム                  |
| `sAKI`        | 頂上。目指す「先」を表す                   |
| `KurIA`       | 頂上到達時、「クリア！」の上に表示する文字 |

## 2. 決定事項

- 3Dの滝を上るアクションゲームにする。
- ゲーム中の操作はWASDによる移動のみとする。
- タイトル画面は設けない。
- 滝を流れるA・K・Iにちなんだ3種類のアイテムで上昇する。
- 3種類それぞれの出現確率・効果量などを個別に設定できるようにする。
- 障害物も滝を流れ、接触するとペナルティが発生する。
- 重力加速度は小さめ、上方向の最大速度は大きめ、下方向の最大速度はかなり小さめにする。
- 後半ほど障害物を多くするなど、高度に応じて難易度を上げる。
- 頂上の `sAKI` に到達するとクリアする。
- クリア画面には、上段に `KurIA`、その下に `クリア！` を表示する。
- ビジュアルは簡易なものとし、約5時間で完成できる規模を優先する。

以下の各節に示す具体的な挙動は、この決定事項を実装するための基本案とする。

## 3. ゲームの流れ

1. 起動すると、そのまま滝とプレイヤーが表示される。
2. 最初のWASD入力でゲームを開始する。開始前は落下とスポーンを待機させる（仮仕様）。
3. 左右移動と上下への補助入力で、流れてくるアイテムに近づく。
4. アイテムを取ると、現在のY速度とアイテムの上昇速度のうち大きい方へ切り替わる。
5. A・K・Iをそろえると追加の上昇ボーナスが発生する（基本案）。
6. 流木を避けながら高度を上げ、`sAKI` を目指す。
7. 頂上到達でゲームを終了し、クリア表示を出す。

1ステージ構成とし、通常プレイで頂上到達まで60〜90秒程度を目安に調整する。
これは所要時間の目安であり、制限時間の設定ではない。

## 4. 操作・移動

### 座標とカメラ

- X軸を左右、Y軸を高度とし、Z軸方向の移動を固定する。
- オブジェクトは3Dで描画し、移動は滝の面に沿った上下左右に限定する。
- カメラは斜め前からの固定角度を基本とし、プレイヤーの高度を追従する。
- プレイヤーを画面の下寄りに置き、進行方向である上側を広く映す。
- 最高速でも障害物を見てから避ける時間を確保する。視認から接触まで約1秒以上を初期の目安とする。

### 入力

| キー | 動作                                                       |
| ---- | ---------------------------------------------------------- |
| A    | 左へ移動                                                   |
| D    | 右へ移動                                                   |
| W    | 上向きの補助加速度を加え、取得した上昇の勢いを長持ちさせる |
| S    | 下向きの補助加速度を加え、下にあるアイテムを狙う           |

- Wの補助加速度は重力の大きさより弱くし、上昇の主力をアイテムにする。
- WとS、AとDを同時に押した場合、それぞれの入力を相殺する。
- 左右に移動できる範囲を設け、滝の外へ出ないようにする。
- プレイヤー自身の衝突による回転は固定し、尾びれなどの見た目だけを動かす。

### 初期調整値（仮）

数値はUnity上の仮のワールドスケールを前提とする。

| 項目             | 初期値 | 単位・補足                            |
| ---------------- | -----: | ------------------------------------- |
| 左右移動速度     |      5 | unit/s                                |
| 重力加速度       |     −3 | unit/s²                               |
| Wの補助加速度    |    ＋1 | unit/s²                               |
| Sの補助加速度    |     −1 | unit/s²                               |
| 上方向の最大速度 |     14 | unit/s                                |
| 内部の上昇速度上限 |   30 | unit/s。実移動の上限を超えた勢いを保持 |
| 下方向の最大速度 |    1.5 | 下向き速度の大きさ。Y速度の下限は−1.5 |
| 移動可能な滝の幅 |     24 | unit。初期実装の12 unitから2倍        |

内部のY速度と実際の移動速度を分ける。重力とW/S補助は内部速度に反映し、上方向は `maxStoredRiseSpeed`（初期値30）、下方向は既存の落下速度上限で制限する。内部上限の有効値は実移動の最大上昇速度以上とする。
実際のRigidbodyのY速度は内部速度を既存の上下の移動速度上限で制限して設定する。内部速度が移動上限を超えている間は、余剰分が重力で減少しても実移動は上限速度を維持する。通常取得・セットボーナスは内部速度に反映する。
通常被弾では内部速度も被弾時の速度へ切り替え、AKI無敵中の接触では保持する。下端で内部の負速度を0にし、開始待機・クリア・再挑戦では内部速度と実速度を0にする。

## 5. A・K・Iアイテム

### 名前と見た目の候補

| 種別 | 名前の候補 | 簡易な見た目                      | 初期出現重み | 初期確率 | 初期上昇速度 |
| ---- | ---------- | --------------------------------- | -----------: | -------: | -----------: |
| A    | アケビ     | 紫色の細長い球＋Aの文字           |            1 | 約33.3％ |     5 unit/s |
| K    | カキ       | オレンジ色の球と緑のヘタ＋Kの文字 |            1 | 約33.3％ |     5 unit/s |
| I    | イチジク   | ピンク色の縦長の球と茎＋Iの文字   |            1 | 約33.3％ |     5 unit/s |

まずは均等確率・同じ効果量で遊びを確認し、その後に種類ごとの差を調整する。
各アイテムに大きな文字を添え、色と形だけに判別を頼らない。
3種類ともPrefabのルートをXYZ一様に1.2倍とし、果物・文字・取得用Colliderをまとめて拡大する。

### 種類ごとに設定できる項目

| 設定項目 | 内容                                             |
| -------- | ------------------------------------------------ |
| 種別     | A・K・Iの識別子                                  |
| 表示名   | アイテム名                                       |
| 出現重み | その種類が選ばれる確率を決める0以上の値          |
| 上昇速度 | 取得後に最低限保証する上向き速度（速度上限まで） |
| 流下速度 | 滝を下へ流れる速さ                               |
| Prefab   | その種類の見た目と取得判定                       |
| 表示色   | 文字・HUD・取得演出に使う色                      |

各種類の設定をInspectorで編集できるようにする。
実装案として、3種類分のScriptableObjectに設定を保持し、スポーナーが参照する構成を想定する。
スポーンの距離間隔と出現位置の範囲は、スポーナーの共通設定とする。

### 出現確率の扱い

出現確率は、3種類の重みを合計して正規化する。

```text
Aの出現確率 = Aの重み ÷（Aの重み＋Kの重み＋Iの重み）
```

- 重みが `1 : 1 : 1` なら、それぞれ約33.3％。
- 重みが `1 : 1 : 2` なら、A＝25％、K＝25％、I＝50％。
- 重み0の種類は抽選対象から外す。
- 全種類の重みが0の場合はアイテム生成を停止する。
- AKIボーナスを使う通常設定では、3種類すべてに正の重みを設定する。
- 取得済みかどうかによる抽選補正は、初期実装では設けない。

### 取得効果

- 取得後の内部Y速度は `max(upwardImpulse, 現在の内部Y速度)` とし、内部速度上限を適用する。実移動には別途既存の速度上限を適用する。通常取得では速度を加算しない。
- 下降中は下向きの勢いを打ち消してアイテムの上昇速度へ切り替え、既にその値より速く上昇していれば現在の速度を維持する。
- 連続取得で上昇の勢いを保ち、AKIセット完成時には別途加算ボーナスを得る。
- すでに取得済みの種類でも、通常の上昇効果は発生する。
- ひとつのアイテムの効果は1回だけ発生させ、取得後は消す。

### 上昇コンボ

- 取得直前の実際のY速度が正なら、取得1個につきコンボを1増やす。種類の重複は問わない。
- 停止・下降した時点で0に戻す。停止・下降中に取得して上昇へ転じた場合、その取得は数えず、上昇中の次の取得から1とする。
- AKI完成時も取得した1個分だけ増やす。AKI無敵中の障害物接触ではコンボを維持する。
- 再挑戦では0から開始する。コンボ自体に速度・スコアへの追加効果は設けない。

### AKIセットボーナス（基本案）

- A・K・Iを取得順に関係なく1種類ずつ集めると発動する。
- 各種類は取得済み／未取得の状態で管理し、同じ種類を複数回取っても蓄積数は増やさない。
- 通常の取得効果に加え、追加の上向き速度を加算する。
- ボーナス量の初期値は＋8 unit/sとし、Inspectorで変更可能にする。
- AKIブースト発動時から0.8秒間は無敵とし、障害物に接触しても減速・被弾扱いにせず、接触した障害物を消す。時間は `akiInvulnerabilitySeconds` としてInspectorで調整可能にする。
- 無敵中に再びAKIを完成させた場合は、その時点から無敵時間を更新する。すでに残っている無敵時間を短縮しない。
- 発動後はA・K・Iの取得状態をすべて未取得に戻す。
- 文字の点灯や短い水しぶきで、完成と発動を伝える。

## 6. 障害物とペナルティ

### 障害物

初期実装は、滝を下へ流れる流木1種類とする。
流木の長さや角度を変えて、同じ素材から見た目の変化を作る。

### 接触時の基本案

- 上昇の勢いを失い、Y方向速度を−1.5 unit/sに切り替える。
- 接触後は0.8秒の無敵時間を設け、同じ流木などへの連続接触を防ぐ。
- 無敵時間が終了した後は、同じ流木への再接触でもペナルティを発生させる。通常の被弾では流木を使用済みにしない。
- AKIブーストによる無敵中の接触は、上記のペナルティを発生させず、その流木を消す。通常の被弾後の無敵では、追加の流木の接触を無効化するが流木は消さない。
- プレイヤーを短く点滅させる。
- 取得済みのA・K・Iは保持する。
- 左右操作は継続でき、次のアイテムで立て直せるようにする。

ペナルティは、強制落下の大きさよりも、得ていた上昇の勢いを失うことを中心にする。
接触後の速度と無敵時間はInspectorで調整可能にする。

## 7. 高度による難易度調整

現在の高度をスタートから頂上までの範囲で0〜100％に換算し、3段階に分ける。

| 区間               | 配置方針                                         | 流木を生成する上昇距離の初期値 |
| ------------------ | ------------------------------------------------ | -----------------------------: |
| 序盤：0〜30％未満  | アイテムを中央寄りに置き、流木を少なくする       |                        30 unit |
| 中盤：30〜70％未満 | 流木を増やし、アイテムを取るための左右移動を促す |                        17 unit |
| 終盤：70〜100％    | 流木をさらに増やし、安全な進路を選ばせる         |                         9 unit |

- 区間の境界と流木の距離間隔はInspectorで調整可能にする。30／17／9 unitは、変更直前の秒設定3／1.7／0.9秒を目安速度10 unit/sで換算した調整開始値とする。
- アイテムは上下の移動距離に応じた生成と、時間経過による追加生成を併用する。`itemSpawnDistance` をInspectorで調整可能にする（画面表示のmではなく実距離、初期値6 unit・現在の調整値4 unit）。方向転換時も上下の移動量を累積し、距離による生成は静止中には行わない。高速移動で複数の間隔を跨いだ場合も処理する。
- 時間による追加生成は `itemTimedSpawnInterval`（初期値1秒）ごとに1個とし、プレイ中は静止・上昇・下降のいずれでも上側の画面外へ生成する。0なら時間生成を停止する。正の間隔の最小値は0.1秒。開始待機・クリア中は生成せず、再挑戦でタイマーをリセットする。種類は距離生成と同じ重み抽選を使い、全種類の重み0なら生成しない。
- 上昇中は画面上端より上、下降中は画面下端より下へ生成する。カメラ追従後に表示範囲とZ=0平面の交点を求め、`itemOffscreenMargin`（初期値2 unit）だけ画面外へ離す。下降先がステージ下端より下になる場合は上側に切り替える。アイテム自体の流下方向は変更しない。
- 開始時のみ、プレイヤーの2 unit上から画面上端の1 unit手前まで、画面内に高さ2 unit間隔でアイテムを配置する。最初のWASD入力時に1回だけ実行し、再挑戦でも初期配置を行う。通常の距離間隔設定とは独立させる。
- 開始後、静止・下降中に取得可能なアイテムがなくなった場合は上側の画面外へ3個を補充し、移動距離の累積をリセットする。全種類の重み0の場合は初期配置と補充も行わない。
- 流木も時間ではなく、初めて到達した高度の距離しきい値ごとに1個生成する。下降・静止・既に通過した高度への再上昇では生成しない。一度処理したしきい値の記録は、流木の消滅やアイテム補充でもリセットせず、再挑戦時のみ最初に戻す。
- 流木の出現位置は常に画面の上側とし、画面上端の2 unit上と、プレイヤーの `spawnAhead + 1` unit上のうち高い側に置く。高速移動で複数の距離しきい値を跨いだ場合も各しきい値を1回ずつ処理する。
- アイテムと流木の流下速度は2.6 unit/sとする（初期実装の2 unit/sから1.3倍）。アイテムは種類ごとの設定を使う。
- アイテムは生成時に1回だけランダムな倍率（初期値1〜3倍）を抽選し、種類ごとの流下速度へ掛ける。全生成経路に共通適用し、その個体の移動中は倍率を変えない。倍率の範囲はGameSettingsの `itemFallSpeedMultiplierMin`／`itemFallSpeedMultiplierMax` でInspectorから調整可能にする。最小・最大が逆の場合は入れ替えて扱い、負の値は0以上に補正する。流木にはこの倍率を適用しない。
- 後半もアイテムの供給を維持し、安全に取得する難しさを上げる。
- 滝の横幅全体を塞ぐ配置や、見えた直後に接触する配置を避ける。
- 障害物の距離間隔は各しきい値の高度に対応する区間を使う。低い区間へ落下しても、処理済みの高度には新たに生成しない。
- 頂上の高さは、通常プレイの所要時間を測って調整する。

## 8. sAKIへの到達とクリア表示

### 到達条件

- 頂上の目標高度を `goalHeight` として設定可能にする。
- 実際の登頂距離は `goalHeight` で調整する。現在の設定は500 unit。
- 高度表示は実際の高度を0〜1000mに換算する。現在の設定では250 unitで500m、500 unitの頂上で1000mとなる。表示用の頂上距離は `displayedGoalMeters` として実距離から独立して調整できる。
- プレイヤーのY座標が目標高度以上になった時点でクリアとする。
- 高速上昇中に頂上を通過しても、到達が判定されるようにする。
- 頂上付近の目印に `sAKI` と表示する。

### クリア時の処理

1. 状態をクリアに切り替える。
2. プレイヤーのゲーム操作、重力、取得判定、被弾判定を停止する。
3. 新しいアイテム・障害物の生成と、既存の流下オブジェクトの移動を停止する。
4. 画面中央に、次の順序で文字を表示する。

```text
          KurIA
         クリア！
```

`KurIA` は必ず上段に置く。大文字・小文字を上記のとおりに統一する。
頂上へ抜ける短い演出やクリア時間の表示は、時間に余裕があれば追加する。

再挑戦は、クリア後にWASDを一度離し、再び押すと最初から開始する方式を候補とする。
クリア直前からの押しっぱなしで、結果表示が即座に閉じないようにする。

## 9. 画面表示

| 表示     | 内容                                                   |
| -------- | ------------------------------------------------------ |
| 開始前   | 滝とプレイヤー、WASDの操作案内、ドラッグ専用の音量バー |
| プレイ中 | A・K・Iの取得状態、頂上までの進行度                    |
| 頂上付近 | `sAKI` の目印                                          |
| クリア時 | 上段に `KurIA`、下段に `クリア！`                      |

AKIの取得状態は、3文字の点灯・消灯で表す。
右上のタイマー下に実際のY速度を `UP 40.0 m/s` のように表示する。上昇は正、下降は負で表示し、実際の速度に `displayedGoalMeters / goalHeight` を掛けて高度表示と同じm単位へ換算する。現在の設定では20 unit/sが40 m/s、−10 unit/sが−20 m/sとなる。文字色は速度0以下で白、上昇速度が高いほど赤へ連続的に変化し、実移動の最大上昇速度で赤にする。内部速度ではなく実移動速度で数値と色を決める。
速度表示の下に `3 COMBO` のように現在のコンボ数を表示し、加算時は短く拡大して白く光らせ、金色へ戻す。0・開始待機・クリア時はコンボ表示を隠す。
速度表示とコンボの間には、実移動の上昇上限を超えて蓄えた内部速度の割合を細いゲージで表示する。内部速度が移動上限以下なら空、内部上限なら満タンとし、取得時は光らせる。
タイトル専用の画面や、開始ボタンは設けない。
音量バーは既存の開始待機画面に表示し、左ボタンを押しながらドラッグしたときだけBGM・効果音の共通音量を変更する。クリックだけ、キー、ホイールでは変更しない。WASDで開始すると非表示にする。

### 音声

| タイミング                            | ファイル                                |
| ------------------------------------- | --------------------------------------- |
| 起動・開始待機からループ再生するBGM   | `flow-基本BGM.mp3`                      |
| アイテム獲得                          | `決定ボタンを押す33-アイテム獲得時.mp3` |
| AKIブースト発動（通常取得音の代わり） | `決定ボタンを押す25-AKIブースト.mp3`    |
| 実際に被弾したとき                    | `キャンセル4-障害物接触時.mp3`          |
| クリア時                              | `歓声と拍手2-クリア時.mp3`              |

BGMは開始待機・プレイ・クリア・再挑戦を通して常にループ再生する。BGM用AudioSourceはシーン切り替えでも保持し、クリア時のフェードや停止、再挑戦時の先頭への巻き戻しは行わない。クリア時はBGMを流したまま、歓声・拍手を別のAudioSourceで1回再生する。追加音声は元のピッチで再生する。
音量は同じ起動中に選んだ値を引き継ぐ。アプリを起動し直したときの共通音量初期値は50％とする。
音声参照・音量バランスは `Assets/_Project/Resources/GameAudio.asset` で調整する。

### 取得・速度・AKIの演出

- 通常取得：取得位置でアイテム色の粒と広がる光の輪を出し、A／K／Iの文字が少し浮いて消える。サケは短く縦へ伸び、下へ白い水しぶきを噴く。対応するHUDカードも拡大・点灯する。
- 実移動速度が取得によって増えたときは、速度数字を約0.15秒拡大する。最高速では赤い光と上向きマークを添える。速度が増えない取得でも、粒・文字・カード・ゲージの光で取得を伝える。
- 上昇速度が高いほど、画面の左右に下向きの水流線を増やし、速く長くする。中央の移動・回避に使う領域は空ける。
- AKI完成：3枚のHUDカードからA・K・Iの文字が画面中央付近へ集まり、光の筋とともに弾ける。既存の専用音に合わせ、金色の水しぶき、発光するサケ、残光、水流線を重ねる。カメラは短く約9％引き、滑らかに戻す。
- AKI無敵が続く間は、サケの周囲の光の輪と残光を維持し、通常被弾時の点滅は行わない。被弾判定・無敵時間・移動速度は従来の設定を使う。
- 5・10・20コンボを初めて通過するたびに、節目の文字と追加の粒・光の輪を出す。停止・下降後に再びその数へ達した場合も発生する。高いコンボほどコンボ文字を暖色へ寄せる。
- 開始待機・クリアでは水流線・取得文字・ゲージ・AKIの残光を消す。再挑戦では新しい演出状態から開始する。BGMや効果音のピッチは変更しない。

演出の秒数・粒数・大きさ・水流線・カメラの引き・コンボの節目は `Assets/_Project/Resources/GameFeel.asset` で調整する。既存のMainシーンを再生成せず、必要な演出オブジェクトを実行時に用意する。演出用乱数はアイテムの抽選から分離する。

## 10. キャラクター・素材方針

キャラクターの最終デザインは未確定。基本案は、滝を上る小さなサケとする。
Unityの基本形状を組み合わせ、素材作成を短時間で終えられる構成にする。

| オブジェクト    | 作成方法の案                                           |
| --------------- | ------------------------------------------------------ |
| サケ            | Capsuleの胴体、平たいCubeの尾びれ、Sphereの目          |
| 3種類のアイテム | Sphereを変形し、色と文字で区別                         |
| 流木            | 茶色のCylinder。短いCylinderで枝を足す                 |
| 滝              | 水色のQuadと、下へ流れる白い細長い板                   |
| 岩壁            | 大きさと角度を変えた灰色のCube                         |
| 頂上            | 水色の水平な面と、sAKIの目印                           |
| 演出            | 小さな白い粒による水しぶき、取得時の拡縮、被弾時の点滅 |

尾びれを左右に振る簡単な動きで泳ぎを表す。
素材の精密さより、下向きの水流、上昇の加速、取得と衝突への反応が伝わることを優先する。

## 11. Unityでの実装方針

- 1シーンで、開始待機・プレイ中・クリアの状態を管理する。
- 3DのRigidbodyとColliderを使い、移動をXY平面に制限する。
- プレイヤーのUse Gravityをオフにし、独自の重力と上下の速度制限を実装する。
- 物理更新はFixedUpdateで行う。
- 各アイテムの設定を3種類のデータに分け、コード変更なしで調整できるようにする。
- 流木、プレイヤー、アイテムをPrefab化する。
- アイテム取得にはTriggerを使う。
- プレイヤーの当たり判定は本体にまとめ、目・尾びれなどの装飾から不要なColliderを外す。
- 背景の滝や水流の見た目は、ゲームの物理判定から独立させる。
- 入力はInput Systemを使う方針とする。作成時点のプロジェクトには未導入のため、実装時に追加する。
- Unity 2022.3のビルド画面はFile → Build Settingsを使う。

## 13. 動作確認の観点

- WASDのみで移動でき、Z方向へずれない。
- 落下速度は低い上限で止まり、取得を続けると大きく上昇できる。
- 各アイテムの効果量を変更すると、その種類の取得時の上昇に反映される。
- 出現重みを変更すると、抽選処理に反映される。短時間の出現回数が確率どおりにそろうことまでは求めない。
- 重み0の種類が出現せず、全種類0でも不正な抽選を行わない。
- 同じ種類の重複取得でも通常効果が得られる。
- A・K・Iがそろうとボーナスが1回だけ発生し、取得状態がリセットされる。
- 最高速でもアイテムと流木の判定が抜けない。
- 流木に連続接触しても、無敵時間中は追加のペナルティを受けない。
- 高度に応じて障害物が増え、終盤も回避と取得の余地がある。
- 頂上を高速で通過してもクリアになる。
- `KurIA` が `クリア！` の上に表示され、クリア後は被弾しない。
- 提出先の実行環境で、起動からクリアまで通して遊べる。

## 14. 採用した基本方針と調整対象

| 項目                 | 採用方針・調整対象                       |
| -------------------- | ---------------------------------------- |
| キャラクター         | 簡易3Dのサケ                             |
| アイテム名           | A＝アケビ、K＝カキ、I＝イチジク          |
| 障害物のペナルティ   | 上昇の勢いを失い、短時間の無敵を付ける   |

| 頂上の高さ・各調整値 | 所要時間と遊びやすさを見て確定           |
| 提出先               | Windows（64bit）                         |

上記の基本方針はユーザー採用済み。頂上高度、出現間隔、効果量などの初期数値は、5時間の制作内で一通り遊べる状態を作りながら調整する。
